# PROMPT — Session 2 de VECTOR (à coller au début d'une nouvelle session, sur un AUTRE ordinateur)

Tu reprends le projet VECTOR : un bac à sable spatial solo pour PC, en Rust, avec un moteur 100 % maison (rasteriseur de lignes sur CPU, police bitmap 5x7, grille de texte 8x10 px, simulation déterministe à pas fixe de 30 Hz, galaxie infinie générée par hachage de la graine, contenu entièrement data-driven en `.ron`). La session précédente a livré les jalons M0 à M10 ; cette session livre la consolidation puis les extensions E1 à E6.

## 0. Situation de départ : dossier de travail VIDE, autre machine
Cette session tourne sur un autre ordinateur que la précédente. Le dossier de travail est vide : rien n'est installé ni cloné. Tout ce qui existe est sur GitHub. Dans l'ordre :

1. **Vérifie l'environnement** (Windows supposé ; adapte si autre OS) : `git --version`, `gh --version`, `rustc --version`, `cargo --version`, `python --version`. Installe ce qui manque (winget : `Git.Git`, `GitHub.cli`, `Python.Python.3`, `Rustlang.Rustup`). Rust : toolchain `stable-x86_64-pc-windows-msvc` ; l'éditeur de liens exige les **Visual Studio Build Tools 2022** avec la charge « Développement Desktop en C++ » (winget : `Microsoft.VisualStudio.2022.BuildTools`, avec `--override "--passive --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`). Ajoute `%USERPROFILE%\.cargo\bin` au PATH de la session si `cargo` est introuvable.
2. **Authentification GitHub** : le dépôt est **privé** (https://github.com/devmarcpro/vector-game, branche `master`). Si `gh auth status` échoue, c'est un vrai blocage : demande-moi de lancer `gh auth login` (ou de fournir un accès) ; ne devine jamais de jeton ni d'identifiants. Une fois connecté : `gh repo clone devmarcpro/vector-game .` dans le dossier de travail (ou dans un sous-dossier si le dossier n'est pas vide), puis vérifie `git log --oneline | head` et `git status`.
3. **Ce qui n'est PAS dans le dépôt** (ignoré ou local) et qu'il faut régénérer : `target/` (compilation), `saves/` (sauvegardes et `settings.cfg`), `*.png` (captures), `bench_tmp/`, `dist/VECTOR/` (le zip `dist/VECTOR.zip` est versionné). Les captures se régénèrent avec `vector-game --snapshot docs/snap_<scène>.png <scène>` (scènes : cockpit, station, market, inventory, mine, pause, tech, rules, options, codex, help, ship, yard, picker…, voir `crates/game/src/main.rs`). Aucune mémoire de la session précédente n'existe : le dépôt et `docs/` sont la seule vérité.
4. **Vérifie que tout marche avant de coder** : `cargo build --release`, `cargo test` (attendu : 147 tests verts, environ 1 min), `cargo clippy --all-targets -- -D warnings` (propre), `cargo run --release -p vector-tools --bin data_check` (« DATA OK »), `vector-game --script scripts/first_flight.txt` (« SCRIPT OK »). Si quelque chose échoue sur cette machine, diagnostique (version de Rust, MSVC, chemins, fins de ligne CRLF/LF) avant d'avancer, et note-le dans `docs/DECISIONS.md`.
5. Lance le jeu une fois (`cargo run --release -p vector-game`) si un affichage est disponible, sinon contente-toi des captures et des scripts.

## 2. Contraintes permanentes
- **Autonomie** : ne me pose pas de questions sauf vrai blocage (authentification, ambiguïté qui change le résultat). Prends les décisions raisonnables, consigne-les dans `docs/DECISIONS.md`, tiens `docs/PROGRESS.md` à jour. **Avant chaque grosse étape, montre-moi un court plan détaillé**, puis exécute sans attendre de validation sauf si je réponds.
- **Dépendances** : winit, softbuffer, serde, ron, postcard, cpal uniquement. Toute autre dépendance exige une justification écrite dans DECISIONS.md.
- **Architecture** : données dans `data/*.ron`, validées au chargement avec des messages clairs (références croisées, masses des recettes, graphes) ; génération déterministe par `hash(seed, coord)`, jamais d'horloge murale dans la sim ; séparation stricte sim / rendu / UI ; sauvegardes = graine + deltas (en-tête `VECT`, **incrémente la version** à chaque changement de format, refuse proprement les versions inconnues) ; LOD de simulation pour garder les performances ; chaque règle ou système nouveau est **testé** (le test doit pouvoir échouer) ; chaque nouvel élément de contenu a une **entrée de codex** générée depuis les données (aucun chiffre écrit à la main) ; aide contextuelle F1 et étapes du tutoriel mises à jour pour toute nouvelle touche ou écran.
- **Style** : le code se lit comme celui qui l'entoure (même densité de commentaires, mêmes noms, mêmes idiomes). Textes du jeu en français, capitales dans l'interface.
- **Vérification sans voir la fenêtre** : tests unitaires, `--snapshot` (PNG headless, que tu peux relire pour vérifier la mise en page), `--script` (scripts dans `scripts/`, rejoués par `cargo test`), `sim_bench` (stabilité/vitesse sur 1/10/100 ans), `balance_check`, `data_check`.
- **Livraison d'une étape** : `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, mise à jour des docs (PROGRESS, DECISIONS, CONTENT, CONTROLS, ACCEPTANCE si pertinent), commit, `git push origin master`. Un commit par étape cohérente, message clair terminé par la ligne de co-auteur fournie par l'environnement.
- **Quirks connus (Windows)** : cargo n'est pas toujours dans le PATH (`%USERPROFILE%\.cargo\bin`) ; dans bash (Git Bash) `cargo` peut être introuvable, préfère PowerShell pour cargo ; les apostrophes cassent les heredocs bash (utilise l'outil Write ou des scripts Python) ; `cargo fmt` reformate le code, donc les patches par ancre échouent : relis le texte réel avant d'éditer, et relis un fichier avant de le modifier ; la police 5x7 n'a pas d'accents (à corriger à l'étape 0) ; les fins de ligne CRLF/LF génèrent des avertissements git inoffensifs ; ne laisse jamais un processus de benchmark ou de jeu tourner en arrière-plan à la fin.
- **Honnêteté** : si un test échoue, si une étape est partielle, si quelque chose n'a pas pu être vérifié (son, rendu, jouabilité), dis-le explicitement, sans minimiser. Ne déclare rien « terminé » sans l'avoir exécuté.

## 3. Mission de cette session
**Étape 0 — Consolidation** (détail dans `docs/ROADMAP.md`) : (1) jouabilité réelle : parcours complet par script (miner, vendre, acheter un module, fonder une colonie, sauter vers une autre étoile) + 3-4 scripts de régression (combat, colonie, FTL, rechargement de sauvegarde), corriger les blocages trouvés ; (2) équilibrage : plafonner nanomatériaux, barres de combustible, diamant, revoir le recyclage, `balance_check` sous 10 avertissements ; (3) performance : comprendre le ralentissement du vol libre sur très longue durée (`sim_bench drift`) ; (4) accents dans la police 5x7 et retrait de la normalisation ASCII des générateurs ; (5) finition : migration ou message clair des sauvegardes, régénérer `dist/VECTOR.zip`, mettre à jour ACCEPTANCE.md.

**Puis les extensions**, chacune découpée en jalons testables comme M0-M10 (plan, implémentation, tests, captures, docs, commit/push) :
- **E1 Planètes détaillées** : cartes de surface générées à la demande (continents, océans, relief), biomes, climats par latitude et saisons, météo et catastrophes, villes issues des colonies, globe en fil de fer avec courbes de niveau.
- **E2 Faune et flore** : espèces par biome, chaîne trophique simulée par populations, usages (nourriture, médicaments, matériaux, chasse, domestication), espèces envahissantes, quarantaine biologique.
- **E3 Biologie** : organes avec santé propre (la santé globale en dérive), greffes/clonage/prothèses, cybernétique par emplacements (énergie, rejet, piratage, maintenance), mutations (mutagènes, hérédité, instabilité).
- **E4 Dialogues et civilisations** : arbres de dialogue data-driven avec conditions et effets, mémoire des relations, civilisations indigènes (culture, langue, diplomatie, premier contact), histoire procédurale (ruines, artefacts).
- **E5 Vue roguelike à la Dwarf Fortress** : exploration à pied en quadrillage de caractères — intérieur du vaisseau (plan généré depuis les modules installés), stations, villes, ruines, épaves, grottes, surfaces planétaires ; tuiles en `.ron`, cartes locales par hachage, lignes de vue, atmosphère/pression/température par tuile, objets, équipe, combat à pied, interactions et dialogues, blessures localisées issues d'E3.
- **E6 Idées annexes** : épidémies à l'échelle station/planète, écologie et terraformation, religions et idéologies internes aux colonies, marché noir (biologie, cybernétique), piratage et guerre électronique, journal du capitaine généré depuis les événements réels.
Garde la jouabilité du cœur (vol, minage, commerce) intacte à chaque étape : les scripts de régression doivent rester verts.
